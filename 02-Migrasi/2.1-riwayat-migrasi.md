## 1. Milestone 1: Python Monolith

**Repository:** `chatbot_rag_pdf`

Versi pertama adalah aplikasi Python monolith yang menggabungkan semua fungsionalitas dalam satu codebase.

### Arsitektur

```
Streamlit UI → FastAPI Backend → Qdrant
                   ↕
           LlamaIndex + Docling + BGE-M3
```

### Stack Teknologi

| Komponen | Teknologi |
|----------|-----------|
| Backend | FastAPI + Uvicorn |
| Frontend | Streamlit |
| Orchestrator | LlamaIndex |
| PDF Parser | Docling |
| Embedding | BAAI/bge-m3 (Dense + Sparse) |
| Vector DB | Qdrant |
| LLM | Switchable (Ollama/Gemini/OpenAI) |
| Reranker | Lexical overlap blend |

### Fitur Utama
-   Upload PDF tunggal via Streamlit
-   Ingestion: Docling → SentenceSplitter → BGE-M3 → Qdrant
-   Retrieval: Hybrid search + RRF + lexical reranking
-   Intelligent Query Router (LLM-based)
-   LLM-based query rewriting
-   Citation enforcement (regex fallback)
-   Configurable via `.env` (alpha, chunk size, provider, dll.)

### Keterbatasan
-   Monolith — tidak bisa scale secara terpisah antara ML dan business logic
-   Reranker hanya lexical overlap, bukan cross-encoder
-   Chunking sederhana (SentenceSplitter), tabel bisa terpecah
-   Tidak ada streaming
-   Tidak ada document management (hanya reset all)
-   Query rewrite via LLM (lambat, butuh API call)
-   Tidak ada citation validation/repair

## 2. Milestone 2: Enterprise RAG System

**Repository:** `enterprise-rag-system`

Migrasi ke arsitektur **2-service** dengan pemisahan jelas antara orchestration (.NET) dan ML pipeline (Python).

### Arsitektur

```
Streamlit UI → Gateway (.NET :8080) → Worker (Python :8000) → Qdrant
                    ↕                         ↕
              Gemini Agents              Docling + BGE-M3
              (Router, Chat,             + Cross-Encoder
               Grounded Answer)
```

### Stack Teknologi

| Komponen | Teknologi |
|----------|-----------|
| Gateway | ASP.NET Core (.NET), Qdrant.Client (gRPC) |
| Worker | FastAPI (Python) |
| Frontend | Streamlit |
| Agent Framework | Nedo.AspNet.AgentOrchestration |
| PDF Parser | Docling (+ OCR opsional) |
| Embedding | BAAI/bge-m3 (Dense 1024d + Sparse) |
| Vector DB | Qdrant (REST + gRPC) |
| LLM | Switchable (Gemini/OpenAI/Ollama/dll) |
| Reranker | BAAI/bge-reranker-base (Cross-Encoder) |
| Vision AI | Switchable (Gemini/Qwen VL/dll) |

### Fitur Baru
-   **2-Service Architecture** — Gateway (.NET) + Worker (Python)
-   **Multi-Agent Pipeline** — 3 agent LLM (router, chit-chat, grounded-answer) dengan resilience
-   **Schema v2 Chunking** — text, figure, table_parent, table_anchor chunks
-   **Cross-Encoder Reranker** — BAAI/bge-reranker-base FP16
-   **Citation Validation + Repair** — auto-regenerate jawaban jika sitasi invalid
-   **SSE Streaming** — `/api/chat/stream` dengan real-time token delivery
-   **Document Management** — list, get, delete per dokumen via Qdrant gRPC native
-   **Rule-Based Query Rewrite** — cepat, gratis, deterministik
-   **Table Parent Expansion** — tabel anchor di-expand ke versi lengkap
-   **Diversity Filter** — max 2 chunks per dokumen
-   **Vision AI** — deskripsi chart/gambar + interpretasi visual tabel SOP
-   **Conversation-Aware Retrieval** — follow-up questions menggunakan riwayat chat
-   **Internal API Key Auth** — komunikasi aman Gateway ↔ Worker
-   **Hexagonal Architecture** (Worker) — ports & adapters pattern
-   **Batch Ingest** — upload multiple PDF sekaligus
-   **Postman Testing Guide** — dokumentasi API lengkap

## 4. Alasan Migrasi

### Kenapa Pindah dari Monolith?

1.  **Separation of Concerns:** ML pipeline (GPU-heavy) dan business logic (I/O-heavy) memiliki profil scaling yang berbeda. Dengan 2 service, masing-masing bisa di-scale independen.

2.  **Technology Freedom:** Gateway memanfaatkan ekosistem .NET yang kuat untuk HTTP handling, DI, dan configuration. Worker tetap di Python karena library ML (Docling, FlagEmbedding, LlamaIndex) hanya tersedia di Python.

3.  **Kualitas Retrieval:** Perpindahan ke cross-encoder reranker dan schema v2 chunking meningkatkan akurasi pencarian secara signifikan, terutama untuk dokumen yang mengandung tabel kompleks.

4.  **Reliability:** Citation validation + repair memastikan setiap jawaban memiliki sitasi yang valid, mengurangi risiko hallucination.

5.  **User Experience:** SSE streaming memberikan pengalaman yang lebih responsif dibanding menunggu jawaban lengkap.

### Trade-offs

| Pro | Con |
|-----|-----|
| Scale independen | Lebih kompleks untuk di-deploy (2 service) |
| Tech stack optimal per concern | Butuh komunikasi HTTP internal + API key |
| Cross-encoder reranker lebih akurat | Startup lebih lambat (2 proses) |
| Citation validation robust | Konfigurasi tersebar di 2 tempat |
