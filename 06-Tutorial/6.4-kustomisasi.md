# 6.4 Tutorial: Kustomisasi — Sesuaikan Sistem dengan Kebutuhan Anda

Tutorial ini menjelaskan cara mengubah perilaku sistem RAG tanpa mengubah kode utama. Semua perubahan dilakukan melalui file konfigurasi.

---

## Apa yang Akan Anda Pelajari

- Cara mengganti provider/model LLM
- Cara mengubah strategi chunking
- Cara menyesuaikan parameter retrieval
- Cara mengaktifkan fitur Vision AI

---

## 1. Mengganti Model LLM

### Di Gateway (Agent Router, Chit-Chat, Grounded Answer)

Edit `gateway/appsettings.json`:

```json
{
  "Gateway": {
    "RouterModel": "gemini-2.5-flash",
    "ChitChatModel": "gemini-2.5-flash",
    "GroundedAnswerModel": "gemini-2.5-flash"
  }
}
```

**Opsi model yang bisa digunakan:**

| Model | Kelebihan | Kekurangan |
|-------|-----------|------------|
| `gemini-2.5-flash` | Cepat, murah, context 1M token | Butuh internet |
| `gemini-2.5-pro` | Lebih pintar dari Flash | Lebih lambat, lebih mahal |
| `gpt-4o-mini` | Patuh instruksi, stabil | Lebih mahal dari Gemini, context 128k |
| `gpt-4o` | Sangat pintar | Mahal |

> **Catatan:** Mengganti model Gateway memerlukan restart Gateway (`dotnet run`).

### Di Worker (Enrichment LLM)

Edit `worker/app/core/config.py`:

```python
# Model utama (jarang diubah, karena Worker tidak generate jawaban)
LLM_MODEL: ClassVar[str] = "gemini-2.5-flash"

# Model cepat untuk enrichment (contextual retrieval, table interpretation)
FAST_LLM_MODEL: ClassVar[str] = "gemini-2.5-flash-lite"
```

> **Catatan:** Mengganti model Worker memerlukan restart Worker (`python3 main.py`).

## 2. Mengubah Chunking

Edit `worker/app/core/config.py`:

### Ukuran Chunk

```python
CHUNK_SIZE: ClassVar[int] = 1024      # Token per chunk
CHUNK_OVERLAP: ClassVar[int] = 200    # Token overlap antar chunk
```

**Panduan tuning:**

| Skenario | CHUNK_SIZE | CHUNK_OVERLAP | Efek |
|----------|-----------|---------------|------|
| Default (seimbang) | 1024 | 200 | Keseimbangan konteks dan presisi |
| Dokumen teknis pendek | 512 | 100 | Chunk lebih kecil, pencarian lebih presisi |
| Dokumen naratif panjang | 1536 | 300 | Chunk lebih besar, konteks lebih lengkap |
| Banyak informasi hilang | Tetap | Naikkan ke 300 | Overlap lebih besar, konteks tak terputus |

> **Penting:** Setelah mengubah chunking, dokumen harus di-**ingest ulang** agar menggunakan parameter baru.

```bash
# Reset dan ingest ulang
curl -X DELETE http://localhost:8080/api/reset
curl -X POST http://localhost:8080/api/ingest -F "file=@dokumen.pdf"
```

### Table Anchors

```python
ENABLE_TABLE_ANCHORS: ClassVar[bool] = True     # Buat anchor untuk tabel besar
TABLE_ANCHOR_MAX_PER_TABLE: ClassVar[int] = 6   # Max anchor per tabel
```

## 3. Menyesuaikan Retrieval

Edit `worker/app/core/config.py`:

### Hybrid Alpha (Keseimbangan Pencarian)

```python
HYBRID_ALPHA: ClassVar[float] = 0.3  # 0.0 = keyword, 1.0 = semantic
```

**Panduan:**

| Nilai | Perilaku | Cocok Untuk |
|-------|----------|-------------|
| 0.1 | 90% keyword, 10% semantic | Dokumen teknis dengan istilah spesifik |
| 0.3 | 70% keyword, 30% semantic | **Default:** dokumen campuran |
| 0.5 | 50-50 | Dokumen naratif |
| 0.7 | 30% keyword, 70% semantic | Pertanyaan konseptual/abstrak |

### Jumlah Kandidat

```python
DENSE_TOP_K: ClassVar[int] = 48      # Kandidat dari Dense search
SPARSE_TOP_K: ClassVar[int] = 48     # Kandidat dari Sparse search
RERANK_TOP_K: ClassVar[int] = 8      # Hasil akhir setelah reranking
MAX_SOURCES: ClassVar[int] = 5       # Sumber yang dikirim ke Gateway
```

**Panduan:**

| Skenario | RERANK_TOP_K | MAX_SOURCES | Alasan |
|----------|-------------|-------------|--------|
| Jawaban lebih detail | 12 | 8 | Lebih banyak konteks ke LLM |
| Jawaban lebih fokus | 5 | 3 | Hanya chunk terbaik |
| Banyak dokumen | 8 | 5 | Default, seimbang |
| Hanya 1 dokumen | 10 | 5 | Naikkan MAX_SOURCES_PER_DOC juga |

### Diversity Filter

```python
MAX_SOURCES_PER_DOC: ClassVar[int] = 2   # Max chunk per dokumen di hasil akhir
```

**Kapan mengubah:**
- Jika hanya punya 1-2 dokumen, **naikkan ke 4-5** agar konteks cukup
- Jika punya banyak dokumen, **biarkan 2** agar jawaban beragam

### Reranking Threshold

```python
RERANK_MIN_SCORE: ClassVar[float] = 0.001   # Minimum skor relevansi
```

**Kapan mengubah:**
- Jika banyak chunk tidak relevan lolos: **naikkan ke 0.01 atau 0.1**
- Jika terlalu sedikit chunk lolos: **turunkan ke 0.0001**

## 4. Mengaktifkan Vision AI

### Deskripsi Gambar/Chart

Edit `worker/app/core/config.py`:

```python
ENABLE_PICTURE_DESCRIPTION: ClassVar[bool] = True       # Aktifkan
PICTURE_DESCRIPTION_PROVIDER: ClassVar[str] = "local"    # atau "gemini_api"
PICTURE_DESCRIPTION_MODEL: ClassVar[str] = "gemini-2.0-flash"
PICTURE_DESCRIPTION_ONLY_CHARTS: ClassVar[bool] = True   # Hanya chart, bukan semua gambar
```

**Efek:** Gambar/chart dalam PDF akan dideskripsikan oleh Vision AI, sehingga bisa ditemukan saat pencarian teks.

### Interpretasi Visual Tabel SOP

```python
ENABLE_TABLE_VISUAL_INTERPRETATION: ClassVar[bool] = True
TABLE_VISUAL_INTERPRETATION_MODEL: ClassVar[str] = "gemini-2.5-flash-lite"
TABLE_VISUAL_ROUTING_MODE: ClassVar[str] = "auto_signal"    # Otomatis deteksi
TABLE_VISUAL_DETECTOR_BIAS: ClassVar[str] = "precision"     # Sedikit tapi akurat
```

**Efek:** Tabel yang berisi flowchart/diagram proses (umum di SOP) akan diinterpretasikan secara visual, menangkap alur yang tidak bisa dideteksi dari teks saja.

> **Penting:** Vision AI memerlukan `GOOGLE_API_KEY` yang valid dan mengkonsumsi kuota API.

## 5. Mengubah Query Rewrite

```python
QUERY_REWRITE_ENABLED: ClassVar[bool] = True    # Aktifkan/nonaktifkan
QUERY_REWRITE_MODE: ClassVar[str] = "rule"       # "rule" (cepat) atau "llm" (lambat)
QUERY_REWRITE_WEIGHT: ClassVar[float] = 0.6     # Bobot query rewrite vs query asli
QUERY_REWRITE_MAX_TERMS: ClassVar[int] = 12     # Max kata dalam query rewrite
```

**Mode `rule` vs `llm`:**

| Mode | Kecepatan | Biaya | Kualitas |
|------|-----------|-------|----------|
| `rule` | Instan | Gratis | Baik untuk query sederhana |
| `llm` | 1-3 detik | Berbayar (API call) | Lebih baik untuk query kompleks |
