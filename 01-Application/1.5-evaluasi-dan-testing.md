## 1. Smoke Test dengan test_rag.py

### A. Tujuan

Script `test_rag.py` adalah **integration smoke test** untuk memverifikasi bahwa pipeline RAG berfungsi end-to-end. Ia mengirim beberapa pertanyaan ke API dan mencetak hasilnya.

### B. Prasyarat

1. API Backend harus berjalan di `localhost:8000`
2. Minimal satu dokumen harus sudah di-ingest

### C. Cara Menjalankan

```bash
# Pastikan API berjalan terlebih dahulu
python3 main.py &

# Jalankan smoke test
python3 test_rag.py
```

### D. Contoh Output

```
================================================================================
QUESTION: Can the traffic analysis application read vehicle plate numbers?
================================================================================

ANSWER:
Yes, the traffic analysis application can read vehicle plate numbers using 
an OCR module integrated with the detection pipeline. [S1] [S2]

--------------------------------------------------------------------------------
SOURCES:
  • S1 | document.pdf | chunk=12 | score=0.034521
  • S2 | document.pdf | chunk=15 | score=0.031205
```

### E. Test Cases Default

Script ini menguji 4 pertanyaan standar:
```python
test_cases = [
    "Can the traffic analysis application read vehicle plate numbers?",
    "What are the main features of the application?",
    "What object detection model is used?",
    "Does the system support tracking vehicles?",
]
```

**Catatan:** Anda bisa mengubah test cases ini sesuai dengan dokumen yang Anda ingest.

## 2. Evaluasi Kualitas dengan evaluate_rag.py

### A. Tujuan

Script `evaluate_rag.py` adalah **quality evaluator** yang lebih komprehensif. Ia menjalankan serangkaian query dan mengukur berbagai metrik kualitas.

### B. Metrik yang Diukur

| Metrik | Deskripsi |
|--------|-----------|
| **success_rate** | Persentase request yang berhasil (HTTP 200) |
| **citation_presence_rate** | Persentase jawaban yang mengandung sitasi `[S1]`, `[S2]`, dll |
| **citation_valid_rate** | Persentase sitasi yang valid (ID sesuai dengan sources) |
| **avg_source_count** | Rata-rata jumlah sumber per jawaban |
| **avg_grounding_overlap** | Rata-rata overlap token antara jawaban dan sumber |

### C. Cara Menjalankan

**Basic:**
```bash
python3 evaluate_rag.py
```

**Dengan opsi:**
```bash
# Custom API base URL
python3 evaluate_rag.py --api-base http://localhost:8000/api

# Custom test cases file
python3 evaluate_rag.py --cases ./my_eval_cases.json

# Save report ke file
python3 evaluate_rag.py --out ./rag_eval_report.json

# Custom timeout per request
python3 evaluate_rag.py --timeout 120.0
```

### D. Format Custom Test Cases

Buat file JSON dengan format:
```json
[
    {"id": "q1", "question": "Apa fitur utama aplikasi?"},
    {"id": "q2", "question": "Model apa yang digunakan untuk deteksi?"},
    {"id": "q3", "question": "Bagaimana cara kerja tracking?"}
]
```

### E. Test Cases Default

Jika tidak ada file custom, script menggunakan:
```python
DEFAULT_CASES = [
    {"id": "q1", "question": "Summarize the key capabilities in the uploaded document."},
    {"id": "q2", "question": "What evidence mentions OCR or text extraction?"},
    {"id": "q3", "question": "What limitations or constraints are explicitly documented?"},
    {"id": "q4", "question": "Which models or tools are named, and what are they used for?"},
    {"id": "q5", "question": "Quote the section that discusses performance or throughput."},
]
```

### G. Penjelasan Grounding Overlap

Fungsi `grounding_overlap()` mengukur seberapa banyak kata dari jawaban yang ditemukan di source text:

```python
def grounding_overlap(answer: str, sources: Iterable[dict]) -> float:
    answer_terms = {tok.lower() for tok in TOKEN_PATTERN.findall(answer)}
    source_blob = " ".join((src.get("text") or "") for src in sources).lower()
    hits = sum(1 for tok in answer_terms if tok in source_blob)
    return hits / float(len(answer_terms))
```

- **Nilai tinggi (0.7-1.0):** Jawaban sangat grounded, kebanyakan kata ada di sumber
- **Nilai sedang (0.4-0.7):** Jawaban cukup grounded dengan beberapa elaborasi
- **Nilai rendah (<0.4):** Perlu investigasi, kemungkinan hallucination

## 3. Unit Testing dengan tests/test_rag_quality.py

### A. Tujuan

File `tests/test_rag_quality.py` berisi **unit tests** untuk fungsi-fungsi di `app/services/rag_quality.py`. Ini menguji logika inti tanpa perlu API running.

### B. Cara Menjalankan

```bash
# Dari direktori rag_app
python3 -m unittest tests/test_rag_quality.py

# Atau dengan verbosity
python3 -m unittest tests/test_rag_quality.py -v
```

### C. Test Cases yang Diuji

1.  **`test_normalize_markdown_text_removes_hyphenation_and_page_markers`**
    
    Memastikan fungsi normalisasi:
    - Menggabungkan kata yang terpotong hyphenation (`obser-\nvation` → `observation`)
    - Menghapus page markers (`Page 1 of 10`)

2.  **`test_document_and_chunk_ids_are_deterministic`**
    
    Memastikan ID generation:
    - Document ID konsisten untuk konten yang sama
    - Chunk ID mengikuti format `{doc_id}:chunk:{index:05d}`
    - UUID valid dan deterministik

3.  **`test_rerank_nodes_promotes_lexically_relevant_chunks`**
    
    Memastikan reranking:
    - Chunk dengan kata-kata query diprioritaskan
    - Meskipun score asli lebih rendah

4.  **`test_build_context_and_sources_returns_stable_source_payload`**
    
    Memastikan context building:
    - Source ID format `S1`, `S2`, dst
    - Metadata lengkap di setiap source
    - Context string mengandung label

### D. Contoh Output

```

test_normalize_markdown_text_removes_hyphenation_and_page_markers ... ok
test_rerank_nodes_promotes_lexically_relevant_chunks ... ok
test_build_context_and_sources_returns_stable_source_payload ... ok

----------------------------------------------------------------------
Ran 4 tests in 0.012s

OK
```

## 4. Interpretasi Hasil

### A. Checklist Kualitas RAG

Gunakan tabel ini sebagai panduan evaluasi:

| Metrik | Target | Tindakan Jika Gagal |
|--------|--------|---------------------|
| `success_rate` | 100% | Cek koneksi API & Qdrant |
| `citation_presence_rate` | > 90% | LLM mungkin perlu prompt lebih ketat |
| `citation_valid_rate` | 100% | Bug di context building |
| `avg_grounding_overlap` | > 0.5 | Retrieval perlu tuning |
| Unit tests | All pass | Fix bug di rag_quality.py |

### B. Debugging Retrieval

Jika `grounding_overlap` rendah:

1.  **Cek HYBRID_ALPHA:**
    ```bash
    # Di .env, turunkan untuk lebih prioritaskan keyword
    HYBRID_ALPHA=0.2
    ```

2.  **Cek chunk quality:**
    ```bash
    # Lihat chunks yang di-retrieve di response sources
    # Apakah chunks mengandung informasi yang dicari?
    ```

3.  **Cek document ingestion:**
    ```bash
    # Re-ingest dokumen jika ada masalah parsing
    curl -X DELETE http://localhost:8000/api/reset
    # Upload ulang
    ```

### C. Menambah Test Cases

Untuk proyek produksi, tambahkan test cases spesifik:

1.  **Buat file evaluasi custom:**
    ```json
    [
        {"id": "exact_match", "question": "Sebutkan judul dokumen secara persis"},
        {"id": "specific_term", "question": "Apa yang dimaksud dengan [istilah teknis]?"},
        {"id": "negative", "question": "Pertanyaan yang jawabannya tidak ada di dokumen"},
        {"id": "complex", "question": "Bandingkan metode A dan B yang disebutkan"}
    ]
    ```

2.  **Jalankan evaluasi:**
    ```bash
    python3 evaluate_rag.py --cases ./custom_cases.json --out ./custom_report.json
    ```

3.  **Analisis hasil** dan iterasi retrieval parameters.

### D. Continuous Testing

Untuk workflow CI/CD sederhana:

```bash
#!/bin/bash
# run_tests.sh

# Start services
docker-compose up -d
python3 main.py &
sleep 10  # Wait for startup

# Run tests
python3 -m unittest tests/test_rag_quality.py
python3 test_rag.py

# Cleanup
kill %1  # Stop API
docker-compose down
```
